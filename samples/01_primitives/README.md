# 01. プリミティブだけ

キューブ・球・円柱の **メッシュ (三角形の集まり)** を作って描く。 SDF もレイマーチングも使わない。

| キー | 動作 |
| --- | --- |
| 1 / 2 / 3 | キューブ / 球 / 円柱 |
| W | ワイヤーフレーム (三角形の辺だけ) |
| N | 色の見方: 光 → 法線 → UV |

題名に、 今の形・色の見方・三角形の数が出る。

## 読む順

1. [`PrimitiveMesh.h`](PrimitiveMesh.h) / [`.cpp`](PrimitiveMesh.cpp) — 形の頂点とインデックスを作る (GPU を使わない計算)
2. [`PrimitiveSample.cpp`](PrimitiveSample.cpp) — GPU へ送る (`upload`) と描く (`drawImplement`)
3. [`shaders/Primitive.hlsl`](shaders/Primitive.hlsl) — 頂点を画面へ移し、 面の色を決める

## メッシュとは

メッシュは **頂点の並び** と、 **3 つずつ組にした頂点の番号の並び (インデックス)** でできている。 3 つの頂点が 1 枚の三角形。

```cpp
struct MeshVertex {
    Float3 position;  // 位置
    Float3 normal;    // 外向きの法線
    Float2 uv;        // テクスチャ座標
};
struct MeshData {
    std::vector<MeshVertex> vertices;
    std::vector<uint32_t> indices;   // 0-1-2 で 1 枚目、 3-4-5 で 2 枚目 …
};
```

- W でワイヤーフレームにすると、 形が三角形でできていることが見える。 球は 32 × 16 の格子 (1024 枚)。 細かくするほど丸くなるが、 三角形の数が増える。
- 頂点を番号で指すのは、 同じ頂点を何枚もの三角形で使い回すため (球の格子の点は 6 枚の三角形が共有する)。

## 法線と UV (N キー)

- **法線** は頂点ごとに持ち、 三角形の中では 3 つの頂点の法線がなめらかに混ぜられてピクセルシェーダーに届く。 だから球は、 平らな三角形でできていても丸く光る。
  N で 「法線」 にすると、 向き (x, y, z) が色 (赤, 緑, 青) で見える。 上を向く面が緑、 +x を向く面が赤っぽい。
- 立方体は、 角の頂点を面どうしで共有しない (面ごとに 4 つ)。 共有すると角で法線が平均されて、 角が丸く光る。
- **UV** は模様を貼るための座標。 N で 「UV」 にすると、 u が赤、 v が緑で見える。 球の経度 0 と 360° の所は位置が同じだが、 UV が 0 と 1 で違うので別の頂点にしてある (継ぎ目)。

## 三角形の向きと裏面のカリング

三角形は **外から見て反時計回り** に並べてある。 パイプラインは反時計回りを表とし、 裏 (内側を向く面) を描かない (`CullMode = BACK`)。

- 向きは 2 辺の外積 $(p_1 - p_0) \times (p_2 - p_0)$ で分かる。 右手の法則で、 これが外を向けば反時計回り。
- 立方体は、 面ごとに 「法線 n・右 u・上 v」 を **u × v = n** になるように選ぶと、 決まった順 (0-1-2, 0-2-3) が反時計回りになる。
- 向きを間違えた三角形は、 カリングで消えて穴に見える。 このリポジトリでは、 全部の三角形の外積が頂点の法線と同じ側を向くことを、 手元のテストで確かめた。

## メッシュに無いもの

メッシュが持っているのは **表面の三角形だけ**。

| 知りたいこと | メッシュ | SDF (次の 02 で見る) |
| --- | --- | --- |
| 表面はどこか | 三角形そのもの | 値が 0 の所 |
| ある点が中か外か | すぐには分からない (光線を飛ばして三角形と何回交わるか数える) | 値の符号ですぐ分かる |
| 表面からの深さ | 分からない | 値そのもの |

透き通った氷で、 厚さで色を付けたり、 芯だけに気泡を入れたりするには 「中か外か」 「深さ」 が要る。 だから本体の氷は SDF で作っている (メッシュでも、 裏面の深さを別に描く・3D テクスチャを別に持つ、 などの工夫で近いことはできる)。
