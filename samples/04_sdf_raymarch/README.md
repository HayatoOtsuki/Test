# 04. SDF × レイマーチング

02 の **SDF** と 03 の **レイマーチング** を組み合わせて、 SDF の形を描くサンプル。
03 では歩幅を一定にしたが、 ここでは **歩幅を 「その場の SDF の値」** にする。 これを **球追跡 (sphere tracing)** と呼ぶ。
形の式は 02 と同じ [`SdfShapes.hlsli`](../02_sdf/shaders/SdfShapes.hlsli) をそのまま使う。

| キー | 動作 |
| --- | --- |
| 1〜8 | 形 (02 と同じ): 球 / 箱 / 角の丸い箱 / トーラス / 足す / 削る / なめらかに足す / 氷 |
| H | 表示: 光を当てる → 1 画素の歩数を色で → 法線を色で |
| S | 影: なし → くっきり → やわらか |
| ↑ ↓ | 歩幅の倍率 k (0.3〜2.0、 0.1 ずつ)。 1 歩 = SDF の値 × k |

試すこと:

1. H で歩数の表示にする。 ほとんどの画素は青 (数歩で済む) で、 **形の輪郭のすぐ外だけ緑〜黄色** になる。 輪郭をかすめる光線は、 表面の近くを通り続けるので、 小股でしか進めない。
2. ↓ で k を 0.3 まで下げる。 見た目は同じだが、 歩数の表示は赤だらけになる (同じ絵に何倍も歩いている)。
3. 4 (トーラス) で ↑ を押して k = 1.3 にする。 輪の穴が消え、 暗い塊になる。 表面を越えて **形の中** で止まり、 そこで光を計算しているため (中の点の法線は外の光の向きと合わない)。 さらに 8 (氷) で k = 1.5 にすると、 **形が消える** (最初の 1 歩で形を飛び越えて、 床まで行ってしまう)。 床の影は k = 1 のまま調べているので残る。
4. S で影を切り替える。 「くっきり」 は当たるか当たらないかだけ。 「やわらか」 は、 形から遠い所ほど影の縁がぼける。
5. H で法線の表示にする。 色 = 法線 × 0.5 + 0.5 (x+ を向く面は赤、 y+ (上) は緑、 z+ は青が強い)。 氷の表面のゆらぎ (6 mm の値ノイズ) が、 法線のむらとして見える。

1. [`shaders/SdfRaymarch.hlsl`](shaders/SdfRaymarch.hlsl) — `SphereTrace` (球追跡)、 `SdfNormal` (法線)、 `SunVisibility` (影)、 `ShadeSdfScene` (まとめ)

## 1. 球追跡 (sphere tracing)

```hlsl
t = 0.0;
for (int i = 0; i < MAX_STEPS; ++i) {
    float d = Sdf(ro + rd * t);
    if (d < HIT_EPS) return true;  // 表面まで 1 mm 未満 → 当たり
    t += d * StepScale;            // SDF の値だけ進む
    if (t > tMax) break;           // 床より遠く (形は床より上にあるので、 もう当たらない)
}
return false;
```

### なぜ表面を越えないか

SDF の値 $\phi(\mathbf{p})$ は 「$\mathbf{p}$ から **いちばん近い** 表面までの距離」。 つまり、 $\mathbf{p}$ を中心に半径 $\phi$ の球を描くと、 **その球の中には表面が 1 つも無い**。
だから、 光線の向きがどちらでも、 $\phi$ だけ進むのは安全。

```
カメラ ●───────────○──────○───○─○○● 表面
        ↑ 1 歩目: φ が大きい   ↑ 表面に近づくほど φ が小さく、 歩幅も小さくなる
```

- 何も無い所は大股、 表面の近くは小股、 と **歩幅が勝手に決まる**。 03 のように 「歩数をいくつにするか」 を決めなくてよい。
- 表面には **近づくだけで、 ちょうどには着かない** (残りの距離の分だけ進むので、 理屈の上では無限に近づき続ける)。 だから 「1 mm より近ければ当たり」 (`HIT_EPS`) で止める。

### 止まる 3 つの条件

| 条件 | 意味 |
| --- | --- |
| `d < HIT_EPS` | 表面に当たった |
| `t > tMax` | 床 (または 20 m 先) まで来た。 形には当たらない |
| `i == MAX_STEPS` (128) | 歩数を使い切った。 当たらなかったことにする |

### 輪郭の近くで歩数が増える理由

光線が形の表面と **ほぼ平行に、 すぐ近くを通る** と、 $\phi$ は小さいままなので小股が続く。 試すこと 1 の黄色い縁がこれ。 ここで歩数を使い切ると、 当たらなかったことになり、 輪郭が少しやせることがある。

## 2. 歩幅の倍率 k

$$t \leftarrow t + k\,\phi(\mathbf{p})$$

| k | 何が起きるか |
| --- | --- |
| < 1 | 安全だが遅い。 同じ点に着くのに歩数が増える (試すこと 2) |
| = 1 | 式が本当の距離を返すなら、 いちばん速くて安全 |
| > 1 | 表面を越えることがある。 越えて中で止まる (色がおかしい) か、 形を飛び越える (消える) (試すこと 3) |

**式が本当の距離を返さない** こともある。 なめらかに足す・削る・ノイズでゆらす、 などをすると、 $\phi$ が本当の距離より **大きく** なる所が出る (02 の等高線の間隔がずれていた所)。
そういう形では k = 1 でも越えることがあるので、 本体の氷は **k = 0.9** にして少し控えめに進んでいる。

## 3. 法線 = SDF の傾き

SDF は 「表面から離れる向き」 にいちばん速く増える。 その向きが表面の外向きの法線。 数学では **勾配** $\nabla\phi$ と書く。

$$\mathbf{n} = \frac{\nabla \phi}{\lVert \nabla \phi \rVert}, \qquad \frac{\partial \phi}{\partial x} \approx \frac{\phi(\mathbf{p} + h\mathbf{e}_x) - \phi(\mathbf{p} - h\mathbf{e}_x)}{2h}$$

```hlsl
const float h = 0.0005;
float3 g = float3(Sdf(p + float3(h, 0, 0)) - Sdf(p - float3(h, 0, 0)),
                  Sdf(p + float3(0, h, 0)) - Sdf(p - float3(0, h, 0)),
                  Sdf(p + float3(0, 0, h)) - Sdf(p - float3(0, 0, h)));
return normalize(g);
```

- 各軸で、 少し前と少し後ろの値の差を取る (**中心差分**)。 $2h$ で割るのは、 `normalize` で長さをそろえるので省いている。
- メッシュ (01) は法線を頂点に持たせて運んだが、 SDF は **どの点でも式から法線が出る**。
- $h$ は小さすぎると計算の誤差 (float の桁) が目立ち、 大きすぎると細かい形がぼける。 ここでは 0.5 mm。 本体は 3D テクスチャの 1 マス (`VoxelSize`) を使う (それより細かい情報は無いので)。

## 4. 影も球追跡

当たった点 (や床の点) から **太陽の方へ** もう一度球追跡する。 途中で形に当たれば、 太陽の光は届かない (影)。

```hlsl
float t = 0.01;                   // 出発点の表面に自分で当たらないよう、 少し離れてから
for (...) {
    float d = Sdf(p + L * t);
    if (d < HIT_EPS) return 0.0;  // 形に遮られた
    if (ShadowMode == 2) visibility = min(visibility, SOFTNESS * d / t);
    t += d;
}
```

- 形の表面の点から出るときは、 法線の方へ 2 mm ずらしてから出発する (`p + n * 0.002`)。 ずらさないと、 出発点で `d ≈ 0` になり、 自分自身に当たってしまう (表面がまだらに黒くなる)。
- 床は SDF に入れていない。 床の点は光線と平面 $y=0$ の交差 $t = -o_y / d_y$ で出して、 そこから同じ `SunVisibility` を呼ぶ。

### やわらかい影

太陽には大きさがあるので、 本当の影の縁はぼける (半影)。 球追跡では、 光線が形に当たらなかった場合でも **途中で形のどれだけ近くを通ったか** が $d$ で分かる。

$$\text{届く割合} \approx \min_i \frac{s \cdot d_i}{t_i} \quad (s = \texttt{SOFTNESS} = 8)$$

- $d_i / t_i$ は、 点 $\mathbf{p}$ から見た 「光線と形の隙間」 の角度の目安。 隙間が狭いほど (または遠くでかすめるほど)、 太陽の一部が隠れているとみなして暗くする。
- 影を落とす物から遠い所ほど $t$ が大きく、 $d/t$ が小さくなりにくいので、 縁が広くぼける。 これは本当の半影と同じ傾向。
- 物理的に正しい計算ではなく、 よく使われる近似 ([参考文献](../../docs/guide/references.md) の Inigo Quilez の記事)。 1 本の光線で済むのが良い所。

## 5. 光の当て方 (簡単版)

```hlsl
float sun = SunVisibility(p + n * 0.002) * saturate(dot(n, L));  // 拡散 (Lambert) × 影
float sky = 0.5 + 0.5 * n.y;                                     // 上を向くほど空の光
float spec = pow(saturate(dot(n, h)), 64.0) * 0.3;               // 鏡面 (Blinn-Phong)
```

形を見るための簡単な光。 本体のメッシュの方は PBR (金属っぽさ・粗さ) を使っている ([docs/03](../../docs/03-ice-component.md))。 SDF の氷は、 ここで出した点と法線から屈折を計算する ([docs/06](../../docs/06-ice-optics.md))。

## 本体の氷との対応

| このサンプル | 本体 |
| --- | --- |
| `SphereTrace` (k は ↑ ↓ で変える、 当たり 1 mm) | [`IceSdfCommon.hlsli`](../../src/ice/shaders/IceSdfCommon.hlsli) の `SphereTrace` (k = 0.9、 当たり 0.5 mm) |
| 最初の `t` は 0、 床までで止まる | 光線と箱の交差で `[tNear, tFar]` を出し、 箱の中だけ進む |
| `Sdf(p)` = 式をそのまま計算 | `SampleSdf(p)` = 3D テクスチャから読む (05 で扱う) |
| `SdfNormal` (h = 0.5 mm) | `SdfNormal` (h = `VoxelSize`) |
| `SunVisibility` (当たるか / 近くを通ったか) | [`IceShadow.hlsl`](../../src/ice/shaders/IceShadow.hlsl) (氷は透けるので、 中を通る長さで色付きの影にする) |

式を毎回計算するのは、 形が単純なら速い。 形が複雑になって式が重くなったら、 **前もって 3D テクスチャに焼いて読む**。 それが 05 と本体のやり方。
