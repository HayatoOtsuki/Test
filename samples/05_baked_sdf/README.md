# 05. SDF を焼いて描く

04 では、 球追跡の 1 歩ごとに SDF の **式** を計算した。 このサンプルでは、 式を **前もって CPU で格子に焼き**、 GPU の **3D テクスチャ** にして、 シェーダーではテクスチャを読むだけにする。
球追跡と法線の出し方は 04 と同じ。 変わるのは 「点 p の距離をどうやって知るか」 だけ。 本体の氷も、 この方法で描いている。

| キー | 動作 |
| --- | --- |
| 1〜5 | 格子の細かさ: 8³ / 16³ / 32³ / 64³ / 128³ (最初は 64³) |
| G | 格子の線を表面に描く / 消す |

タイトルバーに、 格子の点の数・テクスチャの大きさ・1 マスの大きさ・焼くのにかかった時間が出る。

焼く形 ([`BakedShape.cpp`](BakedShape.cpp)) は、 格子の細かさの違いが見えやすいよう、 わざと **とがった所** と **細い所** を入れてある:

- 角のとがった箱 (1 辺 60 cm)。 上の、 最初のカメラに向いた角 (+x +y +z) を、 球でえぐってある
- 箱のまわりに浮かぶ細い輪 (管の太さ 7 cm)

試すこと:

1. 4 (64³) から 2 (16³) にする。 **細い輪が途切れ途切れ** になり、 えぐった所の縁も丸くなる。 さらに 1 (8³) にすると、 **輪は消え**、 えぐった所も無くなって、 箱は角の丸いかたまりになる。
2. 2 (16³) で G を押す。 線の間隔が 1 マス (6.25 cm)。 輪の太さ (7 cm) が 1 マスとほぼ同じなので、 輪がうまく焼けない。
3. 5 (128³) にする。 角も輪もくっきりする。 そのかわり、 点の数は 64³ の 8 倍 (約 210 万点、 8 MB) で、 焼く時間も約 8 倍になる。
4. 3 (32³) で輪の表面をよく見る。 形は残っているが、 表面がわずかにでこぼこしている (マスの境目で、 線形補間の傾きが変わるため)。

## 読む順

1. [`BakedShape.cpp`](BakedShape.cpp) — 焼く形の式 (02 の式を C++ にした物)
2. [`SdfBaker.cpp`](SdfBaker.cpp) — 格子に焼く (CPU だけ)
3. [`SdfTexture.cpp`](SdfTexture.cpp) — 3D テクスチャを作って GPU へ写す
4. [`BakedSdfSample.cpp`](BakedSdfSample.cpp) — キーで細かさを変えたら焼き直す
5. [`shaders/BakedSdf.hlsl`](shaders/BakedSdf.hlsl) — テクスチャを読んで球追跡する

## なぜ焼くのか

| | 式を毎回計算 (04) | 焼いたテクスチャを読む (05・本体) |
| --- | --- | --- |
| 1 歩の重さ | 式の重さしだい。 ノイズや組み合わせが増えるほど重い | いつもテクスチャ 1 回分 (8 点の線形補間) |
| 細かさ | 式のとおり (どこまでも細かい) | 格子のマスの大きさまで |
| メモリ | 要らない | $n^3 \times 4$ バイト |
| 形を変える | シェーダーを書き換える | CPU で焼き直す (式でなくてもよい) |

球追跡は 1 画素で何十歩も進み、 法線でさらに 6 回読む。 形の式が重いと、 それが全部の歩に掛かる。 焼いておけば、 **どんなに重い式でも、 描くときの重さは同じ**。
また、 焼くのは CPU なので、 式でなくてもよい (メッシュから距離を測る、 手で彫った形など)。

## 1. 格子に焼く

立方体の箱 $[\mathbf{b}_{min}, \mathbf{b}_{max}]$ を $n \times n \times n$ のマスに分け、 **各マスの真ん中** で式を計算する。

$$h = \frac{b_{max,x} - b_{min,x}}{n}, \qquad \mathbf{p}_{x,y,z} = \mathbf{b}_{min} + \left( x + \tfrac12,\; y + \tfrac12,\; z + \tfrac12 \right) h$$

```cpp
grid.values[(static_cast<size_t>(z) * size + y) * size + x] = sdf(p);
```

- 並びは **x が最も速く変わる** (1 行) → y (行が積み重なって 1 枚) → z (枚が積み重なって立方体)。 3D テクスチャのメモリの並びと同じなので、 そのまま写せる。
- マスの **真ん中** で焼くのは、 GPU がテクスチャを読むとき、 テクセル $i$ の中心が $u = (i + 0.5)/n$ に当たるから (§3)。 端 ($x = 0$) で焼くと、 半マスずれる。

| 細かさ | 点の数 | 大きさ (float) | 1 マス (箱 1 m) |
| --- | --- | --- | --- |
| 8³ | 512 | 2 KB | 12.5 cm |
| 16³ | 4,096 | 16 KB | 6.25 cm |
| 32³ | 32,768 | 128 KB | 3.1 cm |
| 64³ | 262,144 | 1 MB | 1.6 cm |
| 128³ | 2,097,152 | 8 MB | 0.8 cm |

**1 辺を 2 倍にすると、 点の数もメモリも焼く時間も 8 倍** ($2^3$)。 本体の氷は 64³ (箱 88 cm、 1 マス 1.4 cm)。

## 2. GPU へ写す (SdfTexture)

手順は本体の `generateSDF` と同じ ([docs/05-generate-sdf.md](../../docs/05-generate-sdf.md) §4)。

1. **3D テクスチャを作る**: `D3D12_RESOURCE_DIMENSION_TEXTURE3D`、 `DXGI_FORMAT_R32_FLOAT`、 既定ヒープ (GPU 専用のメモリ)。 最初は `COPY_DEST` (写される先) の状態。
2. **一時バッファに書く**: CPU からは既定ヒープに直接書けないので、 アップロードヒープのバッファに書いてから GPU に写させる。 このとき **1 行 (RowPitch) は 256 バイトの倍数** という決まりがある。 `GetCopyableFootprints` がその並びを教えてくれる。

   | 細かさ | 1 行のデータ | RowPitch (256 の倍数) | 行の後ろの隙間 |
   | --- | --- | --- | --- |
   | 8³ | 32 バイト | 256 | 224 バイト |
   | 64³ | 256 バイト | 256 | 0 |
   | 128³ | 512 バイト | 512 | 0 |

   だから配列を丸ごと `memcpy` せず、 **1 行ずつ** 写している。
3. **写す命令とバリア**: `CopyTextureRegion` で写し、 `ResourceBarrier` で `PIXEL_SHADER_RESOURCE` (ピクセルシェーダーから読む) 状態へ変える。
4. **SRV**: シェーダーから見えるヒープに、 3D テクスチャとして読むための記述子を作る。

### 焼き直すときの注意

キーで細かさを変えると、 次の `drawImplement` で焼き直す (`mBakedSize != mWantedSize`)。

- 写す命令は **記録しただけ** で、 GPU が実行するのはこのフレームの最後。 それまで一時バッファ (`mUpload`) を壊してはいけないので、 メンバーに持っておく。
- 古いテクスチャを捨て、 SRV を上書きしてよいのは、 **前のフレームを GPU が描き終えている** から。 このリポジトリの `Renderer` は毎フレーム GPU を待つ (`waitForGpu`) ので成り立つ。 何フレームも重ねて走らせるエンジンでは、 古い物を GPU が使い終わるまで (フェンスで確かめるまで) 取っておく必要がある。

## 3. テクスチャを読む

```hlsl
float3 uvw = (p - BoundsMin) / (BoundsMax - BoundsMin);  // 箱の中の位置を 0〜1 に
float d = SdfTexture.SampleLevel(LinearClamp, uvw, 0);    // 線形補間で読む
float3 q = max(BoundsMin - p, p - BoundsMax);
return d + length(max(q, 0.0));                           // 箱の外なら、 箱までの距離を足す
```

### 線形補間 (トライリニア)

格子の点と点の間の値は、 サンプラーが **まわりの 8 点を混ぜて** 作る。 マスの中の位置を $(f_x, f_y, f_z) \in [0,1]^3$ とすると

$$\phi \approx \sum_{i,j,k \in \{0,1\}} \phi_{ijk}\; w_i(f_x)\, w_j(f_y)\, w_k(f_z), \qquad w_0(f) = 1 - f,\; w_1(f) = f$$

各軸で 「近い点ほど重く」 混ぜている。 1 次元で言えば、 2 点を直線で結んだ値。

### テクセルの中心

uvw が $(i + 0.5)/n$ のとき、 ちょうどテクセル $i$ の値がそのまま返る。 焼くときにマスの真ん中で計算したので、 **焼いた点の位置と、 テクスチャが値をそのまま返す位置が一致する**。

### 箱の外

サンプラーは 「端で止める (CLAMP)」 なので、 箱の外では端の値が返る。 そのままだと、 箱から遠い点でも表面が近く見えてしまうので、 箱までの距離を足す。 このサンプルは箱の中だけ球追跡するので普段は効かないが、 法線を出すとき箱の外を少し読むことがあるので入れてある (本体と同じ)。

## 4. なぜ角が丸まり、 細い所が消えるか

格子が知っているのは **焼いた点の値だけ**。 点と点の間は直線で混ぜた値になる。

- **細い所が消える**: 形の表面は 「値が 0 になる所」。 マスより細い輪だと、 焼いた点がどれも輪の **外** (値が正) になることがある。 正の値どうしを混ぜても負にはならないので、 そこには表面が無い = 輪が消える。 実際に焼いた値を調べると (箱の柱の外 = 輪だけがある所)、 8³ ではいちばん小さい値でも **+1.25 cm** で、 中の点が 1 つも無い。 16³ では中の点が 64 個あるが、 いちばん深くても −0.36 cm (表面すれすれ) で、 輪に沿って間が空くので途切れ途切れになる。 64³ では中の点が 2,584 個、 いちばん深い所は −2.7 cm (本当は管の真ん中で −3.5 cm)。
- **とがった角が丸まる**: 角の外側の距離は、 角を中心にした丸い形をしている (いちばん近い所が角の 1 点になるため)。 それを粗い点で拾って混ぜると、 値 0 の所は角を通らず、 マス 1 つ分くらいの丸みで内側を通る。
- **えぐった所が埋まる**: 球でえぐった凹みも、 凹みの深さがマスより小さいと、 焼いた点には凹みが写らない。

目安として、 **残したいいちばん細い所に、 マスが 2〜3 個以上入る** 細かさにする。 7 cm の輪なら 1 マス 2.5〜3.5 cm 以下 → 箱 1 m なら 32³ 以上 (試すこと 4 のとおり、 32³ でも少しでこぼこする)。

## 5. 法線と球追跡

04 と同じ。 違うのは 2 つだけ。

- 法線の中心差分でずらす幅 $h$ を **1 マス** (`VoxelSize`) にする。 格子にはマスより細かい情報が無いので、 それより小さくずらしても、 線形補間の折れ目 (マスの境目) を拾ってむらになるだけ。
- 球追跡は、 光線と箱の交差 (スラブ法) で出した **箱の中の区間 [tNear, tFar] だけ** 進む。 歩幅は本体と同じく SDF × 0.9 (線形補間した値は、 本当の距離より少し大きくなることがあるので控えめに)。

### 格子の線 (G)

```hlsl
float3 g = (p - BoundsMin) / VoxelSize - 0.5;  // 焼いた点の上で整数になる座標
float3 f = abs(frac(g + 0.5) - 0.5);           // いちばん近い整数までの距離
```

焼いた点を通る面 (x・y・z のどれかが整数の面) と表面が交わる所を暗くする。 箱の面のように、 格子の面と平行な表面では、 その軸の線を描かない (面全体が線になってしまうため)。

## 本体の氷との対応

| このサンプル | 本体 |
| --- | --- |
| `baked_shape::sdf` (箱 − 球 + 輪) | `IceGenerate.cpp` の `iceShapeSdf` (角の丸い箱 − 球 + ノイズ) |
| `bakeSdf` | `generateSDF` の 2 (CPU で焼く) |
| `SdfTexture::upload` | `generateSDF` の 3〜6 (テクスチャ・一時バッファ・写す・SRV) |
| 全画面の三角形を描き、 画素ごとに箱との交差を調べる | 箱のメッシュの裏面を描き、 箱が映る画素でだけ光線を追う ([docs/05](../../docs/05-generate-sdf.md) §5.1) |
| `SampleSdf` / `IntersectBox` / `SphereTrace` / `SdfNormal` | [`IceSdfCommon.hlsli`](../../src/ice/shaders/IceSdfCommon.hlsli) の同じ名前の関数 (中身も同じ) |
| 表面で光を当てて終わり | 表面で屈折して中へ入り、 03 のように中を進んで吸収と気泡を足す ([docs/06](../../docs/06-ice-optics.md)・[07](../../docs/07-ice-bubbles.md)) |

全画面にしたのは、 サンプルを短くするため。 本体のように箱のメッシュを描くと、 箱が映らない画素ではピクセルシェーダー自体が動かないので、 その分速い。
